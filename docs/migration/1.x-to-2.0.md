# Upgrading from 1.x to 2.0

Draft inventory before implementation. Index and handoff schema versions remain 1.
Layer 0 remains deterministic. No study baseline or study hash is migrated.

| Surface | Current behavior | Why change or retain | Replacement and migration | Risk |
| --- | --- | --- | --- | --- |
| CLI `fix propose links` / `normalize` | Produces whole-file `FixProposalV1` | Replace whole-file mutation binding with region evidence | Submit region edits as `RemediationV1`; regenerate proposals and human approvals | Old proposal JSON cannot be applied |
| CLI `fix approve` / `apply` | Approves by a supplied name and applies whole files | A name alone cannot prove authenticated authority | Trusted caller authenticates humans, validates fresh evidence, and verifies actual writes through region library | Missing caller authority must fail closed |
| MCP `docbridge.proposals` whole-file actions | `propose-links`, `propose-normalize`, `approve`, `apply` use whole files | Match region contract without introducing another mutation engine | Use region proposal, revalidation, approval, application and `DecisionV1` with injected trusted controls | Existing consumers need a coordinated migration |
| Public `FixProposalV1`, schema and proposal helpers | Whole-file library contracts exported | Retain for migration callers until their consumers can move; CLI/MCP must stop using them | Move to `RemediationV1`, `DecisionV1`, `createRemediation`, `revalidateRemediation`, `approveRemediation`, `applyRemediation`, `recordDecision` | Removing exports prematurely breaks callers |
| Legacy index / snapshot / retrieval `sha256-normalized-v1` | Original verifier accepts legacy identity; index gate can pass | Legacy artifacts must be migration guidance only | Regenerate with `ak-docs index`; recreate snapshots and dependent projections using semantic identity | Hashes cannot be compared across algorithms; approvals never transfer |
| Study, benchmark, storage and exact approval normalized hashes | Independent versioned contracts use normalized hashing | Retain: ADR 0010 explicitly preserves study hashes; these are not legacy index identity | No migration; distinguish artifact kind before interpreting algorithm name | Global string replacement corrupts unrelated contracts |
| `index.contentHash` config | Accepts only normalized algorithm even though new index emission is semantic | Align declared configuration with semantic index identity | Configure `sha256-semantic-v1`; legacy setting emits migration guidance | Effective configuration hash changes |
| Memory `ingestDir` and adapter defaults | Configurable playbook directories; rule adapter always reads its fixed default | Configuration must control every selected adapter; preserve configurable notes and entity links | Keep `ingestDir`, add configurable rule directories, centralize documented defaults | Unexpected memory files must not be ingested when explicit paths are supplied |
| Public `ingestAgentMemory` / `ingestCursorRules` | Convenience helpers select fixed paths | Keep callers working with documented defaults and explicit path arguments | Supply configured directories; prefer `ingestMemoryCandidates` | Existing default behavior remains intentional |
| Ecosystem `properties` shim | Deprecated projection of canonical `products` | Retain: pinned upstream artifact and shared consumers still require compatibility | Consumers migrate to `products`; remove only after upstream contract migrates | Local removal violates immutable upstream verification |
| CLI flags / commands / aliases | No active CLI flag or alias is marked deprecated in source or CLI spec | Retain supported commands and short help/version flags | No speculative removals | Removing unmarked surfaces would exceed the requested deprecated cleanup |
| Config adapters `session-export` / `bootstrap-delta` | Schema vocabulary already rejects unsupported adapters | Remove unsupported enum vocabulary; preserve the rejection | Use supported deterministic adapters | Invalid configurations remain invalid |
| MCP legacy Content-Length transport | Accepted alongside newline JSON | Retain: consumer compatibility, no announced removal | New integrations use newline JSON | Removing framing silently breaks old clients |
| Action / plugins / MCPB | Invoke current binary and advertise current tool surface | Keep names and schema-compatible handoffs; update descriptions for region migration | Upgrade package together with clients; use migration guide | No unattended human approval authority is introduced |

No deprecated public type/export annotation was found beyond the whole-file fix
migration surface. Legacy discovery evidence, aliases, service-denied local APIs,
and strict handoff emission are compatibility behavior, not deprecation notices.
